Functional States · v1.0

Defines the visual treatment for offline and error states across hero cards, chat headers, and message rows. Supplements the Ray Component Spec v1.0.

01 — Offline state

Ray unavailable

Used when Ray cannot be reached — service down, no connection, or session expired. The UI signals absence without alarming the user. The interface remains visible but clearly inactive.

02 — Error state

Query failed

Used when Ray is reachable but a specific response failed — search returned nothing, extraction timed out, or a processing error occurred. The header remains active. Only the affected message is flagged.

The error bubble uses the coral spectrum colour (#D85A30) as its signal — the same hue already present in the icon. No new colour is introduced. The header and icon remain fully active because Ray is operational — only the query failed.

05 — Rules

State rules

Do

In the error state, keep the header fully active. The error belongs to the response, not to Ray. Dimming the header implies Ray has failed — it hasn't.

Don't

Use red (#E24B4A) for errors. Ray's coral (#D85A30) is already in the icon spectrum — it signals caution without introducing a foreign colour.

Do

In the offline state, change the descriptor to "Unavailable". It is the only place where the descriptor text changes from "Research Assistant".

Don't

Animate the status dot in offline or error states. The pulse means active. A static dot means something has changed — the contrast is the signal.

Do

Keep error messages brief and actionable. One short label naming the failure + one sentence suggesting next action. Nothing more.

Don't

Show error codes, technical descriptions, or stack traces in the message bubble. This is a research platform, not a developer console.
