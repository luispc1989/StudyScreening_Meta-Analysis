# Study Screening Pipeline Documentation

## Overview

This document describes the current pipeline used to prepare bibliographic records for **initial study screening** in a Master's dissertation project (systematic review / meta-analysis).

The pipeline is designed to be:

- **replicable**
- **traceable**
- **user-friendly** (for researchers with limited programming experience)

### Sources covered
- Web of Science (**WoS**)
- Google Scholar (**GS**) *(planned)*
- Grey Literature (**GL**) *(planned)*

Each source is processed separately first. Screening is performed separately per source. A final merge step will be performed later.

---

## Workflow (high level)

1. Export raw records from a source (e.g., WoS)
2. Run source-specific workbook builder script
3. Fill the source search protocol sheet (`*_search_protocol`)
4. Review and screen records in `*_screening_view`
5. Keep source-level outputs and logs
6. Repeat for GS and GL
7. Run final merge script (future step)

---

## Current implemented script

### `scripts/build_wos_workbook.py`

### Purpose
Creates a cleaned and normalized **WoS screening workbook** with:
- a search protocol sheet (`wos_search_protocol`)
- a full sheet (`wos_full`)
- a screening view (`wos_screening_view`)
- processing/audit sheets
- quality and duplicates reports
- execution log (`run_log.json`)

---

## Outputs generated by `build_wos_workbook.py`

Each execution creates a **run folder** (timestamp-based) containing:

1. `01_merged_cleaned.xlsx`  
2. `02_quality_report.xlsx`  
3. `03_duplicates_log.xlsx`  
4. `run_log.json`  

Optional CSV exports may also be created (depending on script configuration).

---

## Main workbook structure (`01_merged_cleaned.xlsx`)

### Sheet order (WoS)
1. `wos_search_protocol`
2. `wos_full`
3. `wos_screening_view`
4. `file_processing_summary` *(hidden by default)*
5. `input_manifest` *(hidden by default)*

---

## `wos_search_protocol` (manual search documentation sheet)

This sheet is a template for documenting the bibliographic search used in WoS.

### Typical fields included
- `Question`
- `Search protocol in WoS`
- `Database`
- `Editions`
- `Search string`
- `Field`
- `Time limit`
- `Search date`
- `Search location`
- `Number of records`

### Purpose
This sheet improves methodological transparency by keeping key search details inside the same workbook used for screening.

---

## `wos_full` (complete source-level dataset)

This sheet stores the **complete source-level dataset** for WoS, including:

- traceability/provenance columns
- normalized bibliographic metadata
- screening columns (`Label`, `Reason to Exclude`, `Comment`)

### Important note
In this workflow, `Label`, `Reason to Exclude`, and `Comment` in `wos_full` are populated automatically via lookup formulas from `wos_screening_view` using `source_record_id`.

---

## `wos_screening_view` (working sheet for initial screening)

This sheet is the **manual screening workspace**.

### Visible columns (working order)
1. `Title`
2. `Abstract`
3. `DOI`
4. `Label`
5. `Reason to Exclude`
6. `Comment`

### Technical hidden column
- `source_record_id` (used for linking back to `wos_full`)

### Why this view exists
The complete sheet contains many columns and is not ideal for manual screening.  
The screening view improves readability and speed during title/abstract screening.

---

## Hidden technical sheets

### `file_processing_summary` *(hidden by default)*
Per-input-file processing results, including:
- file name/path
- rows read
- rows cleaned
- status (`ok` / `failed`)

### `input_manifest` *(hidden by default)*
Technical inventory of input files used in that run, including:
- file name/path
- extension
- size
- modified time
- SHA-256 hash

These sheets remain in the workbook for reproducibility/audit purposes.

---

## Screening conventions

### `Label` (binary)
- `1` = Include
- `0` = Exclude

### `Reason to Exclude`
Used when `Label = 0`, according to the study-specific decision tree.

### `Comment`
Free-text field for:
- justification of inclusion/exclusion
- ambiguity notes
- additional observations

## Source-level workbook schema

## A) Traceability / provenance
1. `source_record_id`
2. `master_id` *(empty at source-level; filled later in final global merge if used)*
3. `source`
4. `source_priority`
5. `run_id`
6. `source_file`
7. `source_path`
8. `source_row_index`
9. `date_imported`

## B) Bibliographic metadata (normalized)
10. `Authors`
11. `Publication Year`
12. `Title`
13. `Abstract`
14. `Author Keywords`
15. `Source Title`
16. `Volume`
17. `Issue` *(if enabled in the script configuration)*
18. `Begin Page`
19. `End Page`
20. `Article Number`
21. `E-mail Address`
22. `DOI`
23. `DOI Link`

## C) Study screening (initial screening)
24. `Label`
25. `Reason to Exclude`
26. `Comment`

### Total number of columns
- **26 columns** (if `Issue` is included)
- **25 columns** (if `Issue` is excluded)

---

## Why these traceability columns are important

The pipeline includes provenance fields to ensure that each record can be traced back to:
- the source database
- the source file
- the original row
- the exact processing run

This is important for:
- reproducibility
- auditability
- troubleshooting
- later source-level and global merges

Key fields include:
- `source_record_id`
- `source`
- `source_file`
- `source_row_index`
- `run_id`

---

## Rule of use (very important)

### Edit screening decisions only in:
- `wos_screening_view`

Do **not** manually edit `Label`, `Reason to Exclude`, or `Comment` in `wos_full`, because these fields are formula-driven.

## Final merge design (planned)

Because screening is performed **before** the global merge, the final merged dataset should preserve:

- source-level identity (`source_record_id`)
- source database (`source`)
- source-level screening results (`Label`, `Reason to Exclude`, `Comment`)

A new global record identifier (e.g., `record_id` / `final_record_id`) will be created at the final merge stage.

## Recommended usage steps (WoS)

1. Export raw WoS records into the configured input folder
2. Run `scripts/build_wos_workbook.py`
3. Open `01_merged_cleaned.xlsx`
4. Fill `wos_search_protocol`
5. Go to `wos_screening_view`
6. Fill:
   - `Label`
   - `Reason to Exclude`
   - `Comment`
7. Save the workbook
8. Keep the entire run folder (including `run_log.json`)

---

## Reproducibility notes

To ensure methodological transparency:

- Keep raw input files unchanged
- Keep all run folders
- Keep `run_log.json` for every execution
- Do not rename worksheet names manually
- Do not change column names manually
- Apply screening decisions only in `*_screening_view`
